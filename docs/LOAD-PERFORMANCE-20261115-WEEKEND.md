# PTA 周末加载慢：补充诊断与修正

日期：2026-11-15（北京时间）。新版 `20261115-2c6347deb5bb`，源码 `51f8179`，10:09:28 上线。

## 为什么有缓存仍会慢

用户截图显示 PTA701 等待 8 秒，近期画面和完整历史均未完成、共享计划已完成。后续单独测试 PTA 没有复现该次 8 秒空图，不能仅凭之后成功读取就否定截图，也不能确定那一次的唯一原因。

查到两项确定的设计缺口：

1. 以前服务重启后，磁盘虽有完整归档，接口只拿它恢复最多 240 根预览；完整初始化仍依赖进程内行情重新准备好。OSS 已有文件不等于页面能立刻取得完整清单。
2. 会话与品种列表分两次顺序读取，之后才创建图表子页面。历史缓存命中只免去历史文件下载，无法免掉这段启动等待。

09:41 的服务器只读检查中，完整归档只有 PTA、甲醇、纸浆、白银四个品种。缓存按实际访问建立，没有预热整个“全部”目录。PTA 最近保存时间为 09:40:11，但用户与测试访问均可能更新缓存，这不能证明最初截图时已经有 PTA 完整归档。

## 本次修正

- 行情源尚未就绪时，直接从已校验的磁盘清单恢复完整历史，图表和已核对的计划可以先使用；后台继续核验当前行情。
- 缓存显示原保存时间，明确标为“历史缓存 · 行情核验中”。不授予实时资格，不沿用旧进程的增量游标；当前完整数据就绪后再建立新游标。
- 会话和品种列表合并为一次请求，两个窗格复用；旧服务及附带列表异常时仍有兼容回退。
- 预览只读凑足最近 240 根所需的块；相同历史内容不重复写入清单。历史修正、损坏修复、半年裁剪及并发清理保护保留。
- 空图阶段的文案改为“正在读取历史K线”，不再暗示必须等待下一笔报价。

没有归档的品种首次仍需要从行情源读取历史，不能凭空恢复。此次没有自动预热全部品种，也没有改变约 5 秒的行情核对频率。

交易时段应考虑跨午夜夜盘及节假日，不能简单按周末日期推断所有品种状态；以交易所的[交易时间](https://www.shfe.com.cn/services/calenderandholidays/tradinghours/)和[休市安排](https://www.shfe.com.cn/services/calenderandholidays/holiday/)为准。此次将历史读取与实时资格分开，没有按“休市”把旧缓存直接判为最新，也没有新增未经核实的固定节假日日历。

同一电脑、Edge 无界面模式、全新浏览器配置打开 PTA 后刷新一次；默认网络，无人工限速。前后各一轮，不是多轮统计。服务端缓存没有重置，上线公验也可能预热 PTA，不能将此标成服务器冷启动性能。

这次刷新有改善，但全新浏览器首次打开仍慢，不能称为整站秒开。缓存命中不代表没有接口、读取、校验和绘图开销。

首次导航还有明显的 HTTP 实际发送前等待。在本地 `127.0.0.1` 的隔离测试里也观察到约 11.47 秒 requestStart，之后到首字节约 5.9 毫秒，DNS 近零、连接约 2.2 毫秒。因此不能把这段等待直接归因于公网服务器、OSS、DNS、TLS 或代理；这是测量环境仍需单独排查的请求发送前开销。该等待保留在上表首次打开总时间里，没有删除慢样本。

上述前后加载测量均无脚本异常、整包回退或 OSS 回源。后测两场景均完成实时来源核验，表内“完整可用”没有混入仅显示完整缓存的时间。

后测两场景均只有一次合并会话请求、没有独立品种列表请求。冷启动从 HTML 返回到完整核验为 8.895 → 8.431 秒；本轮 OSS 历史块下载窗口却由 1.745 → 3.173 秒，抵消了部分启动收益，这一变慢也保留，没有重测挑选更快的数值。刷新从 HTML 返回到完整核验为 3.585 → 2.597 秒。

## 缺口复现与回归

隔离环境先生成完整磁盘归档，再清空进程内行情，使用生产代码实际的初始化选择函数；将行情源保持在未就绪状态，之后手动释放：

- 首次行情请求后约 2.871 秒显示完整缓存图，此时行情源仍未返回；这是隔离样本，不是公网速度承诺。
- 完整图允许画水平线并保存，但没有实时许可或可用增量游标。
- 双窗、全屏、个人资料浮窗保持正常，窗格高度不变。
- 行情恢复后重新建立游标，已画图层保留。
- 无归档使用另一全新浏览器配置：不伪造历史、不误报已就绪，行情源恢复后再显示。

共 14 项必要浏览器断言通过、无脚本/API错误（浏览器另请求的 favicon 404 不属于行情失败）。早期无归档用例误要求“空的实时响应也不能带服务端游标”；实际旧协议允许它，但浏览器只在三周期完整时才将游标用于增量。该误断言已修正，原失败记录保留，完整归档恢复仍强制无游标。

最终工作台回归：408 项 Python、548 项 Node 全过；全目录 Node 633 项通过；打包与运行检查 28 项运行、25 项通过、3 项按平台跳过；32 项发布及协议保护检查通过。
