# 加载优化执行计划

目标：全部品种自动保留最近半年历史，先显示已有画面，当前 K 线持续更新；双品种互不阻塞。

基线：线上版本 `20261115-ae71268bd1c3`。已有浏览器测试：20 次切换首次画面中位数 165ms；完整校验中位数 3773.5ms。首次访问与缓存命中分别统计。

执行顺序：

1. 取消未显示品种和计划的每 5 秒重复请求，保留双窗实时更新、后台目录预热及切回校验。
2. 父页面统一续期初始化数据，第二窗口避免串行请求会话和品种目录。
3. 预览按内容版本检查；固定坐标引用独立复用，不把旧行情重新标记为实时。
4. 复用未改变的历史分块及结构校验，历史修正、尾部 K 线、风险条件仍重新确认。
5. 实测历史下载并发方案，依据冷缓存与重复访问结果选择；记录请求数、字节和完整可用耗时。
6. 回归测试：断线、重连、历史修正、缓存损坏、切换、双窗、保存与实时刷新；线上冒烟、Git 推送及前后对比报告。

保护要求：不修改用户运行状态文件；不重启用户的 8870 本地服务；不删除历史绘图坐标；不以缓存代替开仓条件确认。每次发布保留可回退版本和最新计划备份。

进度与结果由最终验收报告记录。未经过实测的速度改善不作为结论。
