# 共享工作区自动备份

仅正式入口 `serve_workspace.py` 启动备份线程。它读取运行中 `WorkspaceStore.path` 指向的真实工作区文件，默认是 `$SILVER_DATA_DIR/state/workspace.json`；不根据当前浏览器品种选择文件，不启动行情连接。

## 频率与保留

- 每 5 秒仅检查文件元数据；没有变化时不读取、解析或压缩工作区。
- 真实内容变化后，距离上一次快照至少 30 秒才创建下一份。连续编辑会合并进下一次快照，不为每次鼠标移动创建文件。
- 每 30 分钟创建一份定时快照，即使期间没有修改。
- 分别保留最近 **40 份变更快照、10 份定时快照**，正常清理完成后最多 50 份。两组独立保留，忙碌期间不会挤掉定时恢复点。
- 重启从已验证快照恢复时间和内容基线，避免每次重启制造重复快照。

会话续期、`last_seen` 和重复请求收据不算用户编辑；新浏览器身份、昵称/颜色、个人风险、计划、图层、备注、历史等变化算内容变化。每份快照仍包含原文件全部字节，因此恢复内容完整。自动备份不包括行情账户配置、交易规则、行情缓存或只存在浏览器中的设置/未提交草稿。发布前由运维保存的独立私有备份另行保管，不占上述 50 份。

## 文件、安全与成本

默认目录为 `$SILVER_DATA_DIR/backups/workspace/`，与容器的数据挂载共用持久磁盘，无需新增公开目录或容器权限。Linux 目录权限为 `0700`，归档和状态文件为 `0600`。快照包含会话身份和个人资料，应视为私有文件，禁止放进网站静态目录或提交 Git。

每份 `workspace-时间-change|scheduled-随机值.tar.gz` 使用 gzip 级别 1，内部仅有：

- `workspace.json`：捕获时原始文件的完整字节。
- `manifest.json`：格式、时间、类别、长度及 SHA-256 校验信息，不包含行情密码。

后台线程读取原子替换文件的稳定版本，不持有编辑写锁。归档先写同目录临时文件，再验证压缩内容、校验值及工作区完整规则，最后原子发布。已有归档验证按文件签名缓存，避免每轮重新解压 50 份。损坏归档不占用有效保留名额；只有存在已验证恢复点后才清理损坏的受管归档。备份不会改写原始工作区，也不会自动恢复。

单个源文件超过 64 MiB 时停止本次备份并报告失败，避免后台复制耗尽内存；编辑继续运行。此时应检查工作区增长和服务器容量。磁盘满、权限异常、校验失败只记录错误类型，不输出内容或凭据；至少间隔 30 秒后重试。清理/状态写入失败也会独立重试，不为重试制造重复快照。磁盘不允许删除文件时，保留数量可能暂时超限，状态会标为失败。

## 查看状态与恢复

私有目录中的 `status.json` 给出 `state`、`last_success`、`last_attempt`、错误类型及两类快照数量；时间值为 UTC Unix 秒。备份尚无可用工作区时等待文件创建。目录本身无法写入时，状态文件也可能无法更新，应同时查看 `silver.backup` 日志。备份失败不会让行情或协作服务停止。

离线校验可在受信任的服务器终端执行：

```python
from workspace_backup import verify_archive
verify_archive("/var/lib/SilverResonance/backups/workspace/选定的归档.tar.gz")
```

不要把校验结果或解包内容公开发送。恢复需管理员明确操作：先停止当前工作台服务并保留当前文件，再校验所选归档，仅将内部 `workspace.json` 写到临时文件，按原服务属主和 `0600` 权限原子替换实际工作区路径，最后启动并检查计划。不要直接覆盖运行中的文件，也不要对未知归档使用无约束的批量解包。

自动快照保存在同一台服务器，能帮助恢复误改与近期损坏，不能代替独立磁盘或异地灾难备份。
