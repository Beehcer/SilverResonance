# 本地性能修复验证：首订行情与协作通知

本文记录发布前的本地研发验证；该阶段没有访问生产服务器、连接真实行情账户或执行部署。后续用户授权的2026-11-12线上发布结果见 LIVE-DEPLOYMENT.md。

## 首次打开品种

已安装的 TQSDK 3.10.1 `api.py` 是本次判断的直接依据：`get_kline_serial` 第 754–761 行、`is_serial_ready` 第 2219 行、`create_task` 第 2250 行。

- `get_kline_serial` 在 SDK 循环未运行时会同步等待历史初始化，截止为 `25 + 60 * 合约数` 秒；单合约最长等待 85 秒。
- 原生产路径在主循环外依次申请日线、30 分钟、3 分钟。等待某个新周期时，已有品种缓存的转换和连接通知处理也被延后。
- SDK 的公开 `create_task` 在同一 API 的 `wait_update` 循环中调度协程；循环运行期间，`get_kline_serial` 返回待初始化的序列，不再阻塞等待历史。
- SDK 的公开 `is_serial_ready` 判断历史初始化是否完成。

本地修复将首次订阅放进原 API 的任务中，三个周期同时开始加载。仍使用唯一 SDK 会话，仍保留日线 180、30 分钟 6000、3 分钟 10000 根历史。未就绪序列不能更新缓存或刷新有效时间，已加载品种继续更新。任务调度失败会向上抛出；单周期订阅失败保留失败状态并重试缺少的周期。

任务异常另有两层检查：TQSDK `baseApi.py` 的 `_create_task` 为根任务注册 `_on_task_done`，将异常交由 `_run_once` 抛出；应用在替换已完成任务前仍显式读取 `result()`，避免依赖 SDK 回调才能发现错误。取消的任务只重新申请缺少的周期，不重复申请已存在序列。

这消除了应用主动串行等待造成的阻塞，并不保证行情供应商的首次历史下载在一秒内完成。

## 协作通知

原 SSE 每秒才检查一次计划版本，且每 50ms 复制、序列化在线状态。版本检查分别执行会话鉴权和整份计划读取，每 25 秒断流重连。

本地修复在成功持久化并发布内存状态后通知等待者，光标或预览变化也立即通知。SSE 的版本检查在一次锁中完成，只读取鉴权结果及版本号，不复制完整计划、不为后台检查写入活动时间。保留每秒文件检查，以发现其他进程的更新、撤销会话和损坏文件；保留 5 秒心跳，连接周期改为 120 秒。消息明确携带品种与计划标识，帮助前端拒绝旧页面的迟到事件。

条件通知降低等待延迟和重复工作，但 SSE 仍占用一个 Waitress 工作线程。24 线程配置下，多标签页或大量协作者仍需后续容量验收；不能只靠增加线程解决 CPU、存储或供应商带宽不足。

### 本机 HTTP 双会话实测

2026-11-12 使用 Waitress 3.0.2、24 工作线程、临时 JSON 工作区和两个独立登录会话，经真实回环 HTTP 请求测试。一个会话依次提交 10 次修改，另一个通过持续 SSE 收到对应版本。样本为一个图层的独立测试计划，不读取用户计划，不连接行情。

从发起修改请求到第二个会话读到 SSE 事件，各次耗时为：14.694、14.215、13.626、14.430、14.084、32.063、14.490、15.023、13.928、16.793 毫秒。中位数 14.460 毫秒，最大值 32.063 毫秒。所有事件的品种、计划标识和版本号均匹配，测试服务已关闭。

可使用本地辅助脚本 `backtest/measure_local_sse.py` 重复测量。以上仅验证本机 HTTP 传输和提交唤醒，不代表公网延迟、浏览器绘制速度或多人负载下的性能。

## 离线回归

- `test_workspace_events.py`：即时通知、读取与等待之间的竞态、写入失败不通知、跨进程更新兜底、鉴权失效、损坏文件、计划隔离及心跳。
- `test_workspace_production_feed.py`：同一 SDK 循环、首次订阅不重复、未就绪数据不变成有效行情、已加载品种继续更新、单周期失败重试和调度异常。
- 测试仅使用临时工作区、模拟 SDK 循环和本地子进程，不新建真实行情连接。

## 前端加载与共享图层

- 切换品种会取消旧页面的行情、计划和检查读取，保留正在提交的编辑；后台行情改为单任务逐个刷新，编辑或接收伙伴改动时让路。
- 保留内存与浏览器近期 K 线缓存。首次订阅、读取共享计划、补齐历史分别显示浮层状态，列出各周期是否到齐、等待时间及重试入口；浮层不占布局高度。
- 行情响应慢与协作连接失败使用不同提示，缓存不冒充实时数据；完整三周期未到齐时保持绘图锁定，避免基于截断历史建立错误坐标。
- 计划变化立即触发伙伴读取；若读取过程中又出现新版本，读取完成后立即补取。旧品种的事件、在线状态及菜单不能更新当前页面。保存后只合并检查请求，避免每次输入再次请求整套行情、报价和计划列表。
- 图层大纲、图层操作和右键菜单绑定当前品种、当前计划及本次打开状态。删除全部仍需确认，只处理确认时属于当前计划且未锁定的图层。
- 文本内容支持 Alt+Enter 换行、双击直接编辑、圆点垂直居中；右侧改为多行“内容”，文本不再出现“名称”和“备注”。保留原有存档兼容性。
