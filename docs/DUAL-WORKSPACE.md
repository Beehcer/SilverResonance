# 双品种工作台集成

正式工作台入口 `/` 和 `/workspace` 展示双品种外壳，首次使用一个窗口；从品种列表拖入其他品种后上下并列。全屏作用于整个工作区，默认收起左右侧栏，边缘按钮可独立展开。关闭某个品种只关闭视图，不删除其计划。

单窗时拖到图表上半区可在上方加入第二品种，下半区则在下方加入；高亮虚线框与最终位置一致。原窗保留ID和内容，新窗加载失败则不变更原布局。已有两窗时仍按目标窗格替换，同品种仅切换焦点。

计划管理整行入口已移除，图表布局切换放在品种标题栏。兼容旧运行时的管理节点保持隐藏且不可聚焦，不占用图表空间；已有计划、图上价位、共享保存以及右侧入场/止损功能保留。

## 页面与脚本

- `workspace_web.render_workspace_page()`：桌面默认使用 `workspace-dual.html`；`?pane=pane-a` / `?pane=pane-b` 使用带桥接脚本的完整 `workspace.html`。其他 pane 值返回 400。
- `/static/workspace-dual-runtime.js`：对当前 `static/workspace.js` 调用 `workspace_runtime.adapt_workspace_js(source)`。
- `/static/workspace-dual-chart.js`：对当前 `static/workspace-chart.js` 调用 `workspace_runtime.adapt_workspace_chart_js(source)`。
- 两个函数只返回 JavaScript 字符串，不导入应用、不创建身份、不连接行情或读写共享状态。源代码适配位置必须唯一；位置改变会抛出 `ValueError`，路由返回 503，避免发布不完整的接口。
- `workspace-dual-embed.js` 在运行时之前安装 `window.FullWorkspace`；外壳通过它传递活动窗、布局、侧栏状态及切换检查。`full-workspace:*` 消息须同时验证同源与对应 iframe。

正式页面复用 `/api/workspace/*`、`workspace_session` Cookie、行情缓存和共享计划存储。不会加载样板服务、模拟生成器或样板 `data/`。发布前需验证两份动态脚本能够成功生成，并让打包白名单包含新模块与前端资源。

## 保存与协作边界

- 浏览器继续使用 `resonance-workspace-v1:`，原草稿、个人分组、风险设置保持原有身份与键。只对双窗布局及每窗活动周期新增本地键；已有分组不会被清空，新组为空，打开页面先显示“全部”。
- 切换活动窗口保留原 iframe 及保存任务；未完成文字、绘制、表单或输入法组合会阻止切换。替换/关闭先等待保存，等待结束后再次检查新草稿。保存未成功时保留原窗口。
- 两个窗口各自订阅当前合约/计划的共享事件，并各自更新行情。只有活动窗发送协作光标，后台窗仍接收伙伴修改。外壳先建立会话再创建两窗，避免初次打开产生两个身份。
- 全屏和侧栏开合只属于当前页面，不写入共同计划。退出全屏恢复原右栏开关与宽度，左栏重新显示；刷新恢复普通模式。隐藏右栏前检查未完成编辑。
- 已发送到服务端的旧光标请求在极端延迟下仍可能短暂晚到，活动窗下一次心跳会恢复其位置；此行为不修改计划内容。当前不增加新的协作协议。

## 手机与单窗兼容

手机和平板保留原来的单页只读浏览方式。桌面可使用 `/workspace?view=single` 打开原单窗页面；该入口不加载双窗适配脚本。手机端服务器的写入限制继续生效，不依赖外壳自行判断。

## 验证

`python -X utf8 -B -m unittest test_workspace_dual_runtime` 覆盖 20 项运行时检查，包括生产存储键保留、适配失败处理、活动窗光标、两栏开合保护、保存期间行情更新、点击与拖动区分、退出输入保护和每窗视图恢复。其他双窗、路由与打包验证随项目测试执行。
