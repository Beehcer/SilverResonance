# 首次切换与重新打开加速

2026-11-13 更新：尽快显示目标合约画面，历史与计划核对不重复阻塞首屏。不是逐笔推送；正常行情仍每 5 秒检查一次。实际线上版本与发布验收见 `LIVE-DEPLOYMENT.md`。

- 已看过的品种：每窗内存保留至多32个品种的完整历史，切换立即绘制，再核对行情及协作计划；当前20个品种不会因旧16个上限循环淘汰。只增加保留容量，不预先订阅所有品种。
- 重新打开网页：IndexedDB 临时保存至多32个品种、每周期最近240根、有效期24小时；登录会话恢复后立即读缓存，不等规则及风险请求。浏览器拒绝存储或清除缓存时自动改走网络。预览不是完整历史，不能用作增量令牌基线。
- 首次打开：立即请求完整历史，同时读取磁盘预览和一次网络预览，完整请求不再等待预览。如果完整响应缺少周期，在10秒重试预算内每500ms重试；请求本身仍保留12秒超时，这不是加载硬上限。截止时保留已有预览并继续正常轮询，不用空快照覆盖画面。
- 双窗切品种在保存与草稿保护通过、目标品种已接受后释放外壳操作，加载留在当前窗后台完成；额外评审及报价请求不再阻塞切换。快速连续切换仍按generation隔离旧结果，保存失败仍保留原品种。
- 预览明确标记未完成加载，不作为实时许可、不恢复旧就绪状态；图层和伙伴绘图等待完整历史对齐后显示，避免旧锚点落错位置。补齐失败可轮询恢复，草稿在恢复编辑后继续同步。
- 普通 tick 只替换尾部；新增 K 线追加，同时校正旧尾部。最多补齐 64 根，10000 根窗口同步移除旧头部；历史修订、游标失效、窗口不一致回退完整历史。
- 普通读取复用已验证协作文件；文件签名变化立即重载。保留跨进程锁、原子写、坏文件及丢文件保护。修改仍提交服务器，行情预览缓存不保存或覆盖协作计划。
- 历史行深冻结并结构共享，图表缓存时间刻度和均线，合并同一次切换的重复重绘。

## 验证

本轮140项前端、58项Python相关检查通过，包括20品种多轮增量保留、刷新后20份预览、慢预览/评审不阻塞完整出图、空订阅500ms重试、截止保留预览、迟到结果隔离及保存保护。快速切换后忽略旧品种已排队的窗口状态消息，避免保存布局又跳回旧品种。本地预览使用独立模拟数据，不等同于线上延迟测量。

服务器OHLC缓存只存在于当前进程，服务重启后需要重新订阅；持久化绘图基准不是K线历史。双窗完整缓存各自独立，页面刷新会清空内存，只保留磁盘短预览。因此仍需区分首次打开、同窗返回及重启后的重新加载，不能保证所有切换立即得到实时数据。
