# 在线即时协作审计

审计日期：2026-11-11。范围：工作台前端、协作合并、presence、计划 API 与存储。以下行号对应本次本地审计快照，同时提供函数名方便后续定位。

## 结论与计数

共归纳 **8 类协作缺口**，不按按钮或绘图工具重复计数：**1 类 P0 已修复上线；另外 7 类尚未完整解决**。生产行情性能热修已发布，但第4类的事件管道与阻塞问题尚未完整解决。

目标约定：正常联网时，共同内容的每次有效改动立即发送，伙伴能看到操作过程，服务器自动保存；本地草稿只用于断线恢复，不以手动保存或“应用”作为分享前提。服务端确认前显示同步中，断线时明确提示暂未到达伙伴，不误报已同步。

当前已有“完成后的绘图自动同步”和“现有对象拖动预览”；尚未具备所有新对象从第一笔开始的共享预览。鼠标的 50ms 合并发送，也不等于正式计划或端到端同步只需 50ms。

个人布局、缩放、侧栏、自选和当前工具应默认各自保留。共同编辑的内容需要共享，进入伙伴计划或跟随视角应由用户主动选择，避免打断所有人的观察。

## 8 类缺口与验收条件

### 1. P0：并发拖点覆盖伙伴修改——已修复上线

**已复现：** 本人拖动点 A 时，伙伴把点 B 从 99 改成 101；旧实现松手提交拖动开始时的整组坐标，导致 B 被改回 99。真实 `Chart.down/move/up` 加 `WorkspaceMerge.diff` 能复现，属于数据覆盖。

**本地修复：** `static/workspace-chart.js:235` 的 `objectDragPreview` 在移动和松手时按最新对象合并。单点以稳定 ID 定位；被删除的点或对象不复活；伙伴已锁定时不提交；整对象移动在最新几何上叠加本次位移。区域固定尺寸、线段水平价格和原有吸附语义保持。

**回归：** `test_workspace_ui.cjs:670` 起，覆盖两种预期线、远端改点/插点/删点、删除或锁定对象、整线平移、线段端点、跨休市压缩时间轴的区域与线段。执行 `node --test test_workspace_ui.cjs test_workspace_merge.cjs`，72 项通过；`git diff --check` 通过。

**验证范围：** 代码提交 `e45770d`，发布 `20261111-0acec4651567`。真实图表指针事件与合并逻辑在本地覆盖远端修改于最后一次移动前、移动后到达；公网双会话验证同版本改不同点、删除后并发插点均保留，纳入14项通过验收。最终版浏览器自动化读取超时，因此不把API合并验证表述为公网鼠标操作实测。没有稳定 ID 的旧浪线使用唯一原坐标匹配，无法确定时放弃此次提交。

### 2. P1：新对象创建预览与未完成草稿缺失

自由预期线、趋势线、参考线、水平线段、区域、文字六类创建过程，尚未向伙伴发送完整临时几何；完成后才成为共享对象。已有对象移动的预览不在此缺口内。

证据：`static/workspace-chart.js:174`、`:210`、`:264`、`:272`。新工具只更新本地 `path` 或起终点；`preview_object` 来自现有对象的 `drag.preview`。`static/workspace.js:75` 的 `persistDraft` 不包含未完成 path、拖画几何或新文字输入。正常离开有收笔处理，但崩溃等非正常退出仍有丢失风险。

**补全：** 临时对象使用会话 ID 与临时对象 ID；移动合并发送，完成原子转为正式对象，取消清除；未完成草稿可本地恢复。

**验收：** A 连点 1234 或拖区域时，B 在 A 完成前看到形状；完成只生成一个对象；取消无残留；刷新恢复与断线重连不重复创建。

### 3. P1：多标签共用在线身份和本地草稿槽

证据：`workspace_store.py:412` 按 `user.id` 保存唯一 presence。纯内存 Store 验证：同用户第二标签进入画板 B 后，画板 A 的 presence 从 1 变为 0。`static/workspace.js:14` 的草稿 key 只有用户、合约、画板，同浏览器同画板多标签会写入或删除同一草稿槽；这是代码确认的恢复风险，尚未做浏览器崩溃实测。

**补全：** 用户身份和连接身份分离；presence、跟随目标、草稿及 outbox 增加 tab/client ID。

**验收：** 同浏览器开两个合约、同合约两个计划、同计划两个标签，在线状态不互相踢出；断线分别编辑后两份草稿都能恢复，任一标签保存不能删除另一份未保存草稿。

### 4. P1：计划事件与保存链路存在等待和阻塞——生产性能热修已发布，其余待补全

审计基线：`workspace_api.py:297` 每秒检查版本；`static/workspace.js:61` 的 `pullSharedPlan` 拉取后等待行情 poll，期间新通知因 `state.pulling` 直接返回，没有补拉最高版本标志；`:103` 等行情、评审、计划、报价全部完成才处理结果。`:221` 每次保存还等待画板目录，才释放保存队列。`:54` 的请求超时在响应头返回后即清除，没有覆盖响应体等待。

**补全：** 正式计划事件与行情刷新分离；保留待拉取最高版本；目录读取脱离保存关键路径；完整请求超时。后续评估直接推送差量及事件恢复。SSE 同步线程容量与共享 JSON 存储也需要独立压测，不应仅凭功能测试声称支持任意人数。

**验收：** 慢行情或慢目录不拖住伙伴修改；一次拉取期间连续收到多个版本，最终无需等下一轮轮询便追上最高版本；响应体停滞可超时恢复；记录真实延迟与并发人数。生产热修移除了工作台不用的旧雷达计算，见 [发布记录](LIVE-DEPLOYMENT.md)；本次直连公网通知1.226秒不能代替端到端P95测量，也未消除上述事件链路问题。

### 5. P1：旧计划校验阻挡无关绘图保存

证据：`static/workspace.js:208` 的 `flush` 在任意 patch 前检查整个计划的入场上下界及规则状态。已用真实 flush 逻辑验证：旧上下界相等时，新增 wave 留在 pending，API 调用数为 0。后端同样有计划校验，不能只绕过前端。

**补全：** 将几何、备注持久化与“交易计划能否启用”的校验分开；错误定位到对应交易条件。

**验收：** 带旧错误交易字段的计划仍能共享新增图形、改色、备注；错误条件继续阻止启用或触发判断；修改错误后交易条件恢复检查。

### 6. P2：跨周期临时预览和跟随范围不完整

证据：`static/workspace-chart.js:357` 先按 `peer.period` 过滤。正式日线预期线能映射到小周期，拖动临时几何却仅在同周期显示。`static/workspace.js:93` 的 `applyFollow` 只跟随伙伴当前一张图的视角，不包含整套布局或跨合约、跨计划切换。

**补全：** 临时对象沿用正式对象的周期映射与透明度；区分“跟随视角”“进入伙伴计划”，明确作用范围。

**验收：** 日线预期线拖动时小周期预览与正式态一致；本周期编辑权限不被映射绕过；退出跟随恢复自己的布局和视角。

### 7. P2：文本为整字段最后写入覆盖，缺少共同输入感知

证据：`static/workspace-merge.js:14`、`:37` 按对象属性或计划字段保存字符串；`static/workspace.js:301` 防抖保存整段内容。没有共享文字光标、选区或“正在输入此字段”状态。不同字段的修改可以合并，同一段文字同时输入仍可能互相覆盖。

该行为与当前“编辑者修改优先”的约定并不矛盾，不能当作所有保存都失败。应先明确是否需要两人同时写同一段备注。

**补全：** 优先提供字段级编辑者提示、保留中文输入过程；确有共同长文本需求再引入字符级合并。

**验收：** 不同字段输入互不覆盖；同字段冲突符合已约定策略且有提示；中文组词、焦点和光标不被伙伴刷新打断；若增加字符合并，测试两端同时插入和删除。

### 8. P2：画板目录与共享范围仍容易产生“没有同步”的误解

证据：`static/workspace.js:102` 恢复每个人记住的画板；`:280` 目录每 5 秒刷新。创建计划只自动切换创建者，不会让所有伙伴进入。`:306` 已提供带合约和画板的分享链接，此项属于已实现能力。`:95` 当前房间 presence 为空时回退 session.members，可能展示并非当前计划的成员。

**补全：** 明确显示合约、共享计划、此计划在线人数和伙伴所在计划；目录用创建/归档事件更新；移除不准确的成员回退。

**验收：** 分享链接进入完全相同的合约与画板；新建和归档及时出现在伙伴目录；两个不同计划的内容互不串入；用户能够辨认伙伴在不同计划，而无需猜测同步是否失败。
