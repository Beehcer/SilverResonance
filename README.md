# 多品种期货信号监控（原白银三频共振面板）

本地 web 面板，同时监控12个期货品种。主工作区固定使用 **30分钟结构 + 3分钟确认**，把结构、等待条件、触发、失效、历史目标及1/2手风险放在一起。辅助共振、结构评分和其他周期图表用于补充观察，评分不代表胜率。

## 结构与阶段工作台（2026-10-19）

详情页先展示结构与阶段，再展示真实K线及条件路径，最后核对执行、风险与持仓。总览也优先显示各品种的30分钟阶段。

- 程序区分已有突破/回踩证据、完成K线出现的反弹或回撤、整理候选，并列出下一步需要的证据。界面中的“规则观察”不是交易文档的完整趋势或点位识别。
- 节奏图为教学示意，不与实际K线时间或价位对应。程序不自动推定点3/5/7；可以人工标注结构类型、阶段、点位、当前段和想做的顺势段。选择顺势段时突出3→4、5→6、7→8以及放弃的回撤段；未选择时保持观察。
- 掩体、计划止损、参考目标和平推触发价分开展示。平推条件没有定义时保持“待定义”，不自动用开仓价或固定R倍数填充；人工标注不改变程序计划、预算或交易记录。
- 人工注记保存在当前浏览器localStorage，按合约与结构ID隔离；新结构不能沿用旧编号，新增完成K线时要求复核。历史或过期快照不显示当前确认编号。清除浏览器存储会丢失这些注记，不影响本地成交账本。
- `/api/trade_plan` 的 `structure_context` 提供固定30分钟展示证据，只含最后6根完成K线，独立于下方图表周期。行情暂停时可保留历史结构，不保留可执行计划或风险通过状态。
- 组件位于 `static/structure-model.js`、`static/structure-board.js` 与 `static/structure-board.css`；打包会包含静态文件。

## 30分钟交易计划与个人风险设置（2026-10升级）

- 默认本金 **50,000元**，同一计划最大亏损 **1,000元（2%）**，替代之前讨论的10%上限。试仓、加仓、平仓后的重试合并核算；已有持仓风险与该计划已实现净亏损占用预算。空仓后可点击“开始新计划”，保留历史。
- “等待确认”要求完成30分K线突破后回踩/反抽确认，以及完成3分K线企稳；“提前试仓”显示缺少的确认项。两种模式都要求止损方向有效、有历史目标、当前价未失效或追离结构，以及净收益风险比不低于配置值。
- 每手风险包含止损价差、合约每跳价值、手续费与滑点预留；默认预留2跳是可修改假设。每个品种须填写交易端适用的每手往返预计手续费，未填不视为风险通过。保证金与实际止损成交需在交易端核对，计划预算不保证实际亏损不超过1,000元。
- 总览只有技术与风险均通过的 `ready` 计划进入候选，其余显示等待/失效原因。总览使用确认模式，提前试仓在聚焦页单独选择。
- 持仓管理手工登记已经发生的成交、止损调整、整数手平仓和费用，**不下单、不修改交易端止损**。超预算的实际持仓仍可记录并警示。历史结果仅反映登记内容，不是策略胜率。
- `state/trading_state.json` 原子保存设置、持仓、历史和计划累计；保存失败回滚内存。行情断开、快照超过20秒或品种不匹配时清除旧计划。每笔记录保留成交时合约参数，切品种或换月不会改写历史。

主要接口：`/api/trade_plan?symbol=SHFE.ag2612&mode=confirmed`、`/api/trading/settings`、`/api/positions`、`/api/trading/idea`、`/api/trading/journal`。旧 `/api/entry_check` 已转接同一计划引擎，不再给仓位百分比；`signals_state.json` 的 `decision.plan_status` 与 `max_lots` 为新状态依据，兼容字段 `position_pct=0`。

旧回测修复了未完成K线前视、用当日最终排名挑当日交易、同棒止盈优先、非整数手拆仓与重复统计。新30分钟计划尚无足够独立样本证明高胜率，模拟行情也不能证明盈利能力。

## 这是什么 / 解决什么问题

**需求背景：** 做白银期货日内超短线时，需要同时盯多个周期——大周期定方向、中周期看位置、小周期抓入场时机。人工来回切周期盯盘容易疲劳、错过时机，也容易在情绪驱动下追高杀跌。

**用户诉求：** 以30分钟日内交易为主，快速核对结构与风险，通常1–2手试仓，允许明确标记的提前试探。状态变化写入最近提醒，风险提醒可启用声音并测试。

**它做什么：** 将条件计划、风险核算、辅助图表与手工持仓记录放在一起，帮助核对下一步需要满足什么条件。

**它不做什么：** 不自动下单、不替你做进场决策、不保证盈利。亮灯只是「可以看一眼」，不是「立刻进场」。

## 全局监控层与聚焦层

- **总览页（默认首页）**：12个预设品种的30分钟确认计划、方向过滤、辅助评分和等待原因。仅计划与风险通过才进入候选，点卡片进入详情。
- **全局监控层**：每品种共用30分与3分K线，结构评分也采用30分。全局方向过滤是两周期判断，聚焦页才有完整三周期辅助共振，两者都不等于交易计划通过。
- **聚焦层**：默认辅助组合30分/3分/1分，支持其他组合与7档K线查看；不会改变固定30分/3分计划。顶栏下拉支持热切换品种。
- **信号落盘（openclaw 契约）**：每轮刷新把全品种快照写入 `state/signals_state.json`（exe 运行时写 exe 同目录 `state/`）。结构：

```json
{
  "updated_at": "2025-07-21T10:30:00",
  "symbols": {
    "SHFE.ag2608": {
      "name": "沪银2608", "price": 8120.0,
      "track_a": {"direction": "long", "resonance": true},
      "track_b": {"score": 78, "direction": "long",
                  "pattern": {"found": true, "type": "double_bottom", "L1": 7950, "L2": 7980, "neck": 8110},
                  "support": [{"price": 7980, "score": 82}],
                  "resistance": [{"price": 8260, "score": 74}],
                  "volume_oi": {"quadrant": "价升量增仓增", "healthy": true}},
      "lamp": "red", "entry": 8115, "stop": 7945, "target1": 8270,
      "reasons": ["识别到双底结构：…"]
    }
  }
}
```

数据不足的品种降级为占位条目；`entry/stop/target1` 取自30分钟计划，无有效价格时为null。文件原子写入（tmp+replace），读取方不会拿到半包；使用方应检查 `decision.plan_status` 和快照时间，不能仅按辅助灯色交易。

## 短期走势推演图

总览卡片显示各品种的30分钟结构摘要；详情中的「结构证据与条件路径」默认30分钟，可切换3分、15分和1小时。真实K线图叠加双拐点趋势线、完成K线破线/收回提示和关键反抽/回踩观察区域。先展示各分支的「条件节奏」卡：只表达现价、回测、确认与首个参考位的顺序及相对高低，不按价差或时间比例；不会追加无证据的震荡或反弹。点击节奏卡与条件详情卡同步突出对应分支。下方「价格位置」图仍用于核对真实空间，路径按价差收紧横向间距，每一段均有方向箭头。右侧与历史K线共用价格轴，现价水平延伸到路径起点；默认多分支同屏，点击分支卡片只加粗所选路径，其他有效分支仍保留；也可主动切换“仅看选中”。切分支不改变价格刻度。可查看最近60或120根，外层参考边界始终保留。默认重点分支按当前条件相关性选择，不是概率排名。首个参考位后最多增加两级有历史依据的条件延续，以细点线和空心节点显示；每一级都须先完成收盘越过前级缓冲且后续未收回，并非直接预测到达。参考位未继续延伸时，卡片提示等待守住/受阻与多根重叠证据。

条件分支区分回测后延续、直接延续、局部破线收回和整理观察。下行参考位必须低于现价及触发侧，上行参考位必须高于两者；已跨过的参考位不能继续作为前方目标。关键位分别注明局部已确认拐点和外层冻结边界，局部支撑线收回不会被标成整个结构反转。没有实际整理候选时只列等待证据，不虚构震荡范围或锯齿路径；条件已失效或缺少有效参考位时撤下箭头。路径节点表示条件顺序，不代表到达时间、发生概率或已通过开仓核对。

`market_structure.py` 提供独立可视化证据层：趋势线锚点须经右侧2根完成K线确认，两锚点至少间隔4根；破线事件只能发生在线已可知之后。单根没有延续只提示证据不足，多根缺乏延续及窄幅重叠才产生整理候选，候选不等于已经确认的新震荡结构。长上影只标为当前图表周期的线索，不推断夜盘低开的概率，也不冒充日线收盘判断。可视化层不会改写冻结结构、交易计划、持仓止损或人工文档编号。

图表默认每5秒读取最新订阅快照，切换品种/周期和回到前台时立即读取，也可以点击“立即刷新”。关闭“跟随最新K线”只冻结正在看的图表，后台仍接收行情，交易与风险核对继续运行。K线末根完整显示，但结构确认仍保守排除末根；已过名义周期而没有下一根时显示“等待下一根”，不会据电脑时间补造K线。

行情连接状态、缓存检查时间、行情变化时间与K线时间分开展示。连接与缓存正常而暂时没有变化时显示“最新可用”，不武断认定已休市；失联或缓存中断撤下当前路径。最新可用快照不意味着交易计划通过20秒行情新鲜度检查。数据接收复用天勤持续订阅和更新循环，参见[天勤官方K线说明](https://doc.shinnytech.com/tqsdk/latest/usage/mddatas.html)。

总览同样区分观察与执行：30分钟缓存持续检查、但暂无新变化时，保留参考价、K线日期、结构阶段与关键观察区，归入「夜盘 / 次日预案」。3分钟确认周期未就绪也不隐藏可用的30分钟历史。只有30分钟与3分钟均满足时效检查，才恢复实时计划核对；缓存停更、缺失或断连仍标为不可用。接口的 `display_available` / `view_mode` 用于展示，`realtime` 与兼容字段 `stale` 用于执行时效，预案不得自动晋级为已确认信号。

首次识别用最近8根完成棒之前的最多60根固定参考边界，之后按时间戳增量处理新完成棒。盘中刷新不修改已确认边界和事件，但会依据现价重新检查条件路径是否仍适用、目标是否已被越过；普通窗口滚动不会把已经发生的突破吞回参考范围。摆动点需右侧2根完成K线确认。突破或失败之后，独立整理段至少4根满足窄幅、重叠与上下边界触碰规则，再由后续2根确认，才接替为新平台；形成中的候选保持未确认，失守则取消，原结构仍在。

图中显示当前代号、阶段、切换原因、未确认平台和淡灰旧边界，可展开查看最近事件与旧结构。`state/outlook_state.json` 原子保存完成棒状态，刷新页面或正常重启后继续追踪；品种、合约、周期和最小跳动分别隔离。历史K线修订、时序回退或丢失共同完成棒时明确记录重建原因；损坏或写入失败暂停推演及计划，不静默清空旧记录。模拟数据使用独立内存记录，不污染真实历史。总览、30分推演与交易计划使用同一代参考结构；已手工登记持仓的止损/目标不会随新结构自动改动。

图中参考延伸不是历史目标，交易计划不使用这种延伸制造收益风险比。“参考位触及”仅记录完成K线经过该价位，不代表预测命中、盈利或可推断同一根K线内的先后顺序。行情超过20秒没有变化时暂停实时计划，总览撤下候选；图表可保留最新可用或历史观察。连接中断或计算缓存超过20秒未刷新时暂停绘图。计算更新时间不等同行情更新时间。

接口：`GET /api/outlook?symbol=SHFE.ag2612&period=1800`，周期单位为秒，支持 `180/900/1800/3600`。全品种30分钟和3分钟常驻订阅，其余图表按需加载。

## 三频共振逻辑（轨道A，按交易纪律设计）

| 周期 | 角色 | 判定 |
|------|------|------|
| **30分** | 辅助方向 | 均线排列与斜率 → long / short / none |
| **3分** | 辅助过滤 | 同向且未过度偏离慢均线 |
| **1分** | 辅助执行观察 | 短均线拐头及完成K线企稳，不能代替主计划确认 |

三者同向且各司其职 → **共振**（大灯：做多=红 / 做空=绿，涨红跌绿）。任一环节不满足 → 观望（灰灯）。

> ⚠️ **亮灯 ≠ 可进场。** 面板只判断技术方向对齐，是过滤器不是下单扳机。盈亏比、支撑/压力位、CCL 持仓方向仍须你手动确认。

## 分发使用（给别人用，免安装）

**打包 exe：** 双击 `build.bat` → 生成 `dist\SilverResonance.exe`。

**分发：** 把 `dist\SilverResonance.exe` 单个文件拷到任意 Windows 电脑，双击即可运行，目标电脑**不用装 Python**。

**首次运行：** 会自动开浏览器弹出配置页，让填**自己的天勤账号 + 密码**（免费注册：[shinnytech.com/tqsdk](https://www.shinnytech.com/tqsdk/)）+ 选合约。账号密码与合约存在 exe 同目录 `user_config.json`（密码不会回传前端）。
- 本地 `user_config.json` 不纳入 Git；源码运行可复制 `user_config.example.json` 后填写自己的账号，或通过首次启动配置页填写。
- 同一天勤账号不能多台电脑同时登录，每台机器用各自账号。
- 换月时在配置页改合约代码（如 `SHFE.ag2609`）即可。

**启动进度条：** 每次启动显示进度（起服务→连天勤→校验合约→拉K线→就绪），就绪后自动进面板。连接失败会显示错误 + 重试按钮。

**若卡在「正在拉取三周期K线」：** 行情线程有 30 秒看门狗，超时会自动报错并说明可能原因，不会永久卡住。常见原因：
1. 合约非当前主力 / 已换月（去配置页改成当前主力合约）。
2. 同一天勤账号在别处已登录（同账号不能多台设备同时在线）。
3. 当前为非交易时段且无历史缓存。

## 快速开始（开发/源码运行）

### 1. 装依赖（建议用虚拟环境）
```powershell
cd d:\SilverResonance
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2. 先用模拟模式看界面（无需网络/账号）
`config.py` 里默认 `MOCK_MODE = False`（连真实行情）。想先离线看界面，把它改成 `True` 再跑：
```powershell
python app.py
```
浏览器打开 http://127.0.0.1:8848 ，能看到大灯随模拟数据在做多/做空/观望之间切换。

### 3. 接真实行情
1. 到 [天勤量化官网](https://www.shinnytech.com/tqsdk/) 注册免费账号（快期账号）。
2. 编辑 `config.py`：
   - 填 `TQ_USER` / `TQ_PASSWORD`
   - 把 `MOCK_MODE` 改为 `False`
   - 换月时改 `SYMBOL`（如 `SHFE.ag2609`）
3. 重新 `python app.py`。

## 更新合约与历史 K 线

关闭正在运行的面板，避免同一天勤账号重复连接，然后执行：

```powershell
python fetch_klines.py --force
```

脚本使用本地已保存的天勤账号，查询 12 个品种的实际主力合约，并更新日线、1 小时、15 分、3 分、30 秒五档主力连续 K 线。主力映射保存在 `state/contracts.json`；K 线写入 `backtest/klines/`，1 小时数据同时更新 `backtest/cache/`，供现有回测脚本使用。输出包含成功、跳过、失败数量与数据时间范围；下载失败保留原文件并返回非零退出码。

面板启动时也会联网核实主力合约；暂时无法查询时优先使用 7 天内的有效映射缓存，再回退到月份推算。短周期历史长度受行情账号可返回的根数限制，不能用目标天数推断实际覆盖天数。源码与 EXE 各自使用所在目录下的 `state/`。

## 可调参数（都在 config.py）
- `MA_FAST` / `MA_SLOW`：均线周期
- `TREND_SLOPE_MIN`：趋势斜率门槛（太敏感就调大）
- `OVEREXTENSION_PCT`：过度延伸保护，越小越严格（越不容易在追高时亮灯）
- `POLL_INTERVAL_MS`：前端刷新频率
